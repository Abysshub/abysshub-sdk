# abysshub libraries

The public `abysshub` libraries for JavaScript and Python, and the agent skill `abyss-widget` that ships with them. This file holds only the words the sdk adds; the platform terms (Widget, Creator, Result, Test Run, Creator Environment, …) follow in a section generated from the api's glossary. `docs/adr/0001` says what the publish command does with them.

## Language

**Port**:
A Widget its Creator's own coding agent built, following the `abyss-widget` skill, from a tool the Creator already had somewhere else: a flow, a script, a notebook, an app. Only a tool shaped like a function ports: inputs in, a Result and files out. A tool driven by triggers, schedules or a sign-in on every run is declined.
_Avoid_: migration, import, clone, conversion

**Case**:
One recorded use of the original tool: the inputs it was given and what it produced. A Port is checked against a handful of them, from ordinary uses to one that should fail cleanly. A Template's Cases are the same thing (abysshub-templates).
_Avoid_: test case, fixture, example (an Example Run is the platform's)

**Done List**:
What one Port must do, written by the agent for that tool and confirmed by the Creator before any code is written: which Cases it uses, what each must produce, what may vary and what must hold.
_Avoid_: spec, acceptance criteria, contract

**Check**:
Running a Port on its Cases and judging each against its Done List as passed, failed, or not run (a secret it needs is missing). It runs on the Creator's machine while the agent works, then once on Abyss through the Widget's private link before the Port is done. It claims that the Port works and makes sense on these Cases, never that it equals the original.
_Avoid_: proof (it promises more than a Check gives), parity, verification, Test Run (the platform's run of a Candidate)

**Widget**:
A published Python project — a `run.py` entrypoint plus dependencies and supporting files — with a declared input form, runnable by anyone on the platform.
_Avoid_: script, app, product (the Eloquent model name is `Product` for legacy reasons; the domain term is Widget)

**Draft**:
A Widget-in-creation persisted from the create wizard's first step, before it has been named; it appears nowhere but the create wizard and its Creator's own **Studio**, behind that Studio's Drafts filter. It has nothing live, so its Candidate is its whole project rather than an edit to one. Nobody but its Creator has ever seen it, so when nothing about it — row, Project Version or run — has moved for a week it is swept: erased whole, row and footprint, with nothing to retain and no one to restore it for.
_Avoid_: pending widget (pending is a review status of a named Widget, not a Draft), unnamed product, deleted draft (Deleted is a Widget's state and keeps the row; a Draft is swept and leaves none)

**Project Version**:
One immutable snapshot of a Widget's Python project. Every save creates a new one; none is ever edited in place. A Project Version is **staged** while its files are arriving, **committed** once it has been validated as complete, and **live** once the Creator has Published it — at which point the previous Project Version is deleted. Building its image proves nothing about it; only Publish makes it live. Only a change to files builds: a version saved with exactly its Base Version's files runs on that version's image, so a save that changed only the Widget Interface costs no build.
_Avoid_: revision, release (every save makes one, including saves to a Draft — no publishing decision is implied), unqualified "version" (Harness Vintage and image tags are versioned too)

**Junk**:
An entry of a Creator's project folder that no working Widget can depend on, by how Abyss runs a Widget: editor and version-control folders, caches, virtual environments. The uploader leaves it out and names it under the tree. A root `.env` is not Junk: it is left out too, but its values move into the Widget's **Creator Environment**. Everything else is the Widget's content and reaches its run, whatever its name.
_Avoid_: dotfiles (a leading dot decides nothing: `.streamlit/` is content), ignored files

**Source**:
A Widget's Project Versions and the images built from them. Its Creator and Admins see it; nobody else does, by any route. A run's outputs and previews are results, not Source, even when they carry code the Creator chose to put there.
_Avoid_: code, project files (one Project Version's files are part of the Source, not all of it), repo

**Base Version**:
The Project Version an edit is made from, which is always the one the Creator sees. When they open Edit it is the live version, or a Draft's Candidate, which is that Draft's whole project. After their own Test Run press in that sitting, it is the Candidate that press made. A save names it and takes from it every file it did not change or delete. The save is refused when another tab has moved the Widget past it. A Draft's very first save has none.
_Avoid_: source, baseline, parent, base (unqualified — the Widget Runtime's base image is a different thing)

**Widget Interface**:
The input form a Creator declares for a Widget — an ordered list of Fields a Runner fills before a run. It reaches every run as a run-time input and is never part of the image, so it can change without a rebuild.
_Avoid_: interface_json (the column), form (the rendered artifact), schema

**Candidate**:
A committed Project Version together with the Widget Interface that goes with it, kept apart from what Runners run. A Test Run is what makes one — nothing of the edit, project files or interface, reaches the platform before that press — and Publish is what consumes it. A Widget has at most one; the next Test Run replaces it; only its Creator can run it, and discarding it changes nothing for anyone else. On a live Widget it is never handed back: the wizard always opens what is live, and every edit is made from its Base Version, so a later sitting never builds on or resumes a Candidate nobody published. It is unreachable and is swept. On a Draft it is the whole project, so it is handed back and never swept on its own — it goes only with the Draft, when the Draft is swept.
_Avoid_: draft (a Draft is a whole Widget that has nothing live yet), edit in waiting (nothing waits — an unpublished edit lives in the Creator's browser tab and dies with it), pending version, unpublished changes (the Candidate is a complete project, not a diff), staged version (staged files are still arriving; a Candidate is complete)

**Test Run**:
The Creator's run of a Candidate — free, theirs alone to make, and the only run that can satisfy the Publish Gate. Asking for one is also what saves the edit: the press opens a Project Version, uploads the project and commits it, so a Candidate and its first Test Run are born together. The first press of a sitting makes one even when nothing changed, so a Creator can always prove and publish exactly what they see. It proves exactly the files and interface it ran with; change either and the Candidate needs a fresh one. A Creator running their live Widget makes an ordinary run, not a Test Run.
_Avoid_: test (unqualified), smoke run (the operator's platform-health run against a designated widget), the Creator's run of the live Widget

**Publish**:
The Creator's one act that makes a Candidate live: its files and interface replace the previous Project Version, and the Test Run that passed the gate becomes the Example Run. For a Draft it also names the Widget. Approval is the automatic consequence — nobody reviews anything — and a listed Widget stays listed throughout. Publish creates, starts and builds nothing on the runtime: the machine that ran the Candidate's Test Run is already parked with the Candidate's image, and becomes the live machine by the image becoming live — so the first run after Publish is a warm Pool Hit.
_Avoid_: deploy, approve (the consequence, not the act), save (Listing Fields save without publishing)

**Publish Gate**:
What Publish requires and nothing more: a succeeded Test Run of the Candidate exactly as it stands, plus, for a Draft, the listing minimum (a name, a thumbnail, at least one tag) — which a live Widget already meets, so for a Candidate the gate is the Test Run alone.
_Avoid_: validation, required fields

**Example Run**:
The run shown on a Widget's page so people can inspect real outputs before paying — the latest succeeded Test Run of the version that is live, chosen at Publish and replaced at the next. Earlier ones stay in the run history.
_Avoid_: shared run as a synonym (the Example Run is a Shared run; not every Shared run is the Example Run), demo run

**Output Text**:
The words that stand for one output of an **Example Run** on a Widget's page, so that a person or a search engine learns what the Widget gives without opening a file. For an output that holds text, they are read out of it; for a picture or a video, they are a short description written once, when the Example Run is set at Publish. The Creator sees the Output Text and can correct it. It is a result, never **Source**. No page shows it yet; the api makes and keeps it.
_Avoid_: output preview (a preview shows the file itself), caption, alt text, summary (bare)

**Result**:
The structured answer a Widget may give a run beside its files: the JSON it writes to `output.json`, kept with the run when the run ends. Optional — a Widget without one answers with files only, and is no less callable.
_Avoid_: output (the run's files), response, return value

**Shared**:
A state of a run: anyone who can see its Widget may open it by its link — outputs, inputs and downloads alike, signed in or not. Shared runs are never listed: the Example Run is shown on its Widget's page, and every other Shared run is reached only by its link. A run that is not Shared is its Runner's alone. Publish shares the Example Run; a Shared run of a Widget nobody can see (Frozen, Deleted) is closed with it, except to its own Runner — but a Shared run of a Widget whose Creator deleted their account stays open, since it is what its Runner made.
_Avoid_: public run (it follows the Widget's visibility, it has none of its own), published run (Publish is a Widget act), demo run, listed run (no list of Shared runs exists)

**Held Input**:
A file a Runner has uploaded into a Field of a run that has not started yet. Nobody can read it, the Runner included; it becomes that run's input when the run starts. Unpressed, it is deleted a day after upload; pressed but still waiting in line, seven days after upload, and the run ends refunded. Replacing or removing the file in the Field abandons it.
_Avoid_: staged input or staged file (staged is a Project Version's state and a Staged Member is the Widget Runtime's), draft input, temp file, pending upload

**Last Opened**:
When a run was last opened by anyone who may open it: its Runner, on the website or through an API Key, or anyone through its Shared link. Opening means reading the run itself — its page, one of its files or its folder download, or the run through the API. Appearing in a list is not opening, and neither is an Admin looking at it. A run's end is its first opening. It is shown beside the run's date, it orders a Runner's runs, and a big run falls Asleep only when it is long past.
_Avoid_: last viewed, last accessed, last used

**Pinned**:
A run its Runner chose to keep at hand: it sits above their other runs and never falls Asleep; pinning an Asleep run wakes it. Only its Runner pins or unpins it, and there is no limit on how many. Unpinning is done from the run itself, so it is also an opening.
_Avoid_: favourite, starred, bookmarked, saved (a Widget placed in a Cave is Added, and the glossary already turns those words away there), kept

**Asleep**:
A big run nobody has opened for six months: its files are kept in deep storage, and its Runner can wake them, which takes up to half a day and ends with a Bell notification and an email. Meanwhile everything else about the run — its record, its Result, its small files — stays readable. Only big runs fall asleep; a light run stays readable at once for good, and nothing is ever deleted for its age. A Pinned run, a Shared run, the current Example Run and a Runner's latest run of each Widget never fall asleep, so nobody but its Runner ever meets an Asleep run. Waking is an opening, so a woken run sleeps again only after another six months unopened. Nobody is warned beforehand and no date is shown; only an Asleep run says so.
_Avoid_: archived (in most apps it means hidden from a list), frozen (a Widget's state), cleared, expired (nothing is gone), cold

**Recently Deleted**:
A run its Runner deleted within the last 30 days. Nobody can open it, its Shared link included, and its files stop being readable at once, links already handed out included. Its Runner can restore it, and everything comes back as it was; an Admin still sees it. After the 30 days nobody holds it any more, so it is swept: its files and everything it held — inputs, Result, logs, the notifications and votes that point at it — are erased for good, except the activity record's copy of its inputs, Result and logs, which is kept for security until that record's own 180 days run out. Only a bare line of what it was stays hidden — who ran which Widget, when, how it ended, what it cost, whether it was a Free Run, through which Surface — beside the money it moved in the ledger, so what it counted for (Free Runs, the free API runs, the Spend Cap, Standing) still counts. Only a run that has ended can be deleted, and never the current Example Run.
_Avoid_: deleted (bare — Deleted is a Widget's state, which keeps everything and only an Admin restores), trashed, archived, removed

**Listing Fields**:
The parts of a Widget that describe it rather than run it — title, description, tags, price, thumbnail, visibility, free-run limit. They save immediately and need no Candidate and no Test Run, because none of them can break a run; a thumbnail and one tag are the listing minimum a Draft must have to Publish, the rest is quality.
_Avoid_: metadata, settings

**Publish File**:
The file at the root of a Creator's project folder, `abyss.json`, that tells a publish through an **API Key** what to publish: the Widget's **Listing Fields** and which Widget the folder is. It is never part of the Widget's content and reaches no run. The first publish writes the Widget's number into it, so the next publish of that folder is a new version of the same Widget. It also keeps what the Widget was at the folder's last publish or pull, so a publish can tell that the website moved since and stop.
_Avoid_: manifest, config, listing file (it also says which Widget the folder is)

**Test Inputs**:
The values a Creator's project folder gives for the Fields of its **Widget Interface**, in `test_inputs.json` at the folder's root, so that a **Test Run** can be made with nobody there to type. A file Field names a file inside the folder. They are part of the folder and go up with it, as `interface.json` does. A Field they leave out takes its default.
_Avoid_: example inputs (the Example Run is a run, not a file), fixtures, sample data

**Frozen**:
A listed Widget taken off the Catalog because runs of its live version ended in faults of the Creator's code run after run, or ended run after run in nothing but Budget Exceeded or platform faults the run reported itself, while other Widgets' runs were not failing — one failed run is an input, a streak is evidence. A build of its live version that fails on the Creator's side (a package that does not install, a refused package, a missing project file) freezes it at once, because a build has no input and one failure is already evidence; a build the platform failed to start never freezes. Evidence lifts it the same way it imposed it: the Creator's own run of the live version succeeds, or a Candidate is Published. A frozen Widget leaves search and every listing the moment it freezes, exactly as a private one does, and to everyone but its Creator it is not found by its address; its Creator sees it, is told which run froze it and why, and may run it. Every fault of a listed Widget is announced to its Creator before any freeze is.
_Avoid_: banned, suspended, disabled (nothing is judged — a freeze is evidence, and evidence lifts it), pending (a frozen Widget was published and will be again), paused / temporarily unavailable (a public notice that a Widget faulted is what the 404 exists to avoid), Stopped (an Admin's act, which only an Admin lifts)

**Stopped**:
A link, a Widget or an account an Admin has stopped, which only an Admin can lift. A Stopped link or Widget is not found by anyone but its Creator, who cannot run it; a Stopped account can press, upload and call nothing, its Widgets and links are not found, and its run files are unreadable from the stop and erased 30 days later unless the stop is lifted. It is always an Admin's judgment, never something the platform does on its own, and the Admin always writes the reason, which its owner is sent.
_Avoid_: banned, suspended, blocked, disabled, deactivated, Frozen (a freeze is evidence, and evidence lifts it), **Payments Paused** (a dispute pauses only a person's buying and paid runs), Deleted account (the person's own choice), takedown, delisted (a Stop is how an Admin takes down a link, a Widget or an account)

**Payments Paused**:
A person whose buying and paid runs a dispute on their payment has paused, while their Widgets and everything else carry on. A won dispute lifts it by itself; after a lost one, only an Admin can. A refund never causes it, and while it lasts their Prime or Plan doesn't renew.
_Avoid_: payments stop, stopped (that is an Admin's judgment), blocked, suspended

**Report**:
A notice from anyone, signed in or not, that a Widget or a Discussion post breaks the law or the Terms. It names a reason from a short list and carries a note, and a signed-out reporter leaves an email address. It waits in the Admin Panel, where an Admin may remove what it points at (Stopping a Widget, taking down a post) or Stop the account behind it, always writing the reason its owner is sent; a Report never acts on its own.
_Avoid_: flag, complaint, ticket, takedown request (the Admin's act is the takedown; the Report only asks for a look)

**Cave**:
A user's personal space on the platform, gathering their account, **Prime**, the Byssium they spend, their **API Keys**, and the Widgets they **Added** and viewed. Everything in it is its owner's alone, except that a user with no **Studio** is shown to others as their Cave: who they are, and nothing they keep. The Cave holds the Byssium a user spends (the balance, the **Subscription Allowance**, top-ups).
_Avoid_: profile page (the Cave contains more than profile data), dashboard

**Studio**:
A Creator's place for their work, beside their **Cave**. Its Creator manages and watches their Widgets there, sees how others use them and sets what surrounds them; everyone else sees only what it offers: its name and its public Widgets, with the **Brand**'s logo while its Creator holds **Pro**. Others see a Creator as their Studio. A user has one from the first Widget they start creating, and keeps it for good, even once every Widget they made is **Deleted**. It holds what their Widgets brought in (the **Withdrawable Balance**, withdrawing, the monthly payout, a **Frozen Earning**).
_Avoid_: shop, store, storefront, profile, dashboard, workspace (a Max account's parts are **Spaces**), Creator Cave

**Studio Address**:
The one handle a **Studio** is reached by, at `abysshub.com/studio/<address>` and at `<address>.abysshub.com`. Every Studio has one from the start, filled from its name (which starts as its Creator's username) and changeable, with reserved names and lookalikes of well-known brands refused; an Admin can take one back, and the Studio gets a new one at once; a link's secret part, never the address, finds its Widget, so changing it never breaks a link already sent.
_Avoid_: subdomain (one of its two forms), slug, brand address (it is every Studio's, on every plan), shop slug

**Added**:
The relationship between a user and a Widget they placed into their Cave from the marketplace. Only a Widget, never a **Draft**, is Added.
_Avoid_: favorited, bookmarked, saved

**Deleted**:
The state of a Widget after its Creator removes it: gone from the Catalog, search, its own page and every Cave (the Creator's and everyone who Added it), while its past Runs, the Byssium they earned, its project files and its Creator Environment are all retained; only an admin can restore it, never the Creator.
_Avoid_: archived (implies the Creator can bring it back), unpublished / removed from the marketplace (those describe leaving the Catalog only, not every surface), erased / purged (nothing is destroyed — an abandoned Draft is what gets erased, and that is called swept), swept (a sweep takes what nobody holds; a Deleted Widget is held by everyone whose runs it made)

**Verified**:
The state of a user whose email address has been confirmed with a Verification Code. Until then they can sign in, browse and start creating, but every action that spends or earns Byssium, publishes a Widget, or speaks in public — running, building, reviewing, discussing, answering, voting, following, reporting, paying out — asks them to verify first. A user becomes Verified once, and the state never reverts.
_Avoid_: authorized (the verify dialog's title; authorization is what a session grants, not what a code proves), activated, confirmed

**Verification Code**:
The six-digit code emailed at registration and on every resend, valid for three hours; it is typed into the verify dialog or carried by the emailed link. Resending before it expires sends the same code again.
_Avoid_: verification link (the link merely carries the code), token (that is what a session holds)

**Deleted account**:
An account its person deleted, from their **Cave** or by asking an Admin. For its first 30 days, signing in offers Restore, which brings everything back as it was. Then it is swept: everything that says who they were is erased, and only a bare line of the account stays, so the ledger, the bare lines of runs and what other people made with its Widgets still point at something. Its **Earned Byssium** is still paid to its person as it clears; its **Purchased Byssium** ends at the sweep.
_Avoid_: closed account, deactivated, erased account, Deleted (bare — a Widget's state, which keeps everything and only an Admin restores), Recently Deleted (a run's 30 days), Stopped (an Admin's act, which only an Admin lifts)

**Session**:
A user's standing sign-in: a token the platform honours. A login mints one, good for six months; it ends in exactly two ways — the user logs out (that token only; other devices keep theirs) or the platform refuses it as no session (expired, revoked, account gone), answered with `errors.code = no_session`. A request the platform could not serve — a timeout, a fault, a throttle — says nothing about the Session, and a client must not end one on it.
_Avoid_: login state, token (the token is what a Session holds), 403 (the refusal is a 401; clients read the code, not the number)

**API Key**:
A named key a Verified user creates in their Cave, holding a secret, so their code, or an agent they run, acts as them without a browser. Its runs are its user's runs — their wallet, their Free Runs, private to them — and their Surface is the API. Through the API a key reads only the runs it made, so a key handed to one client never reads another's; its user sees every key's runs on the website, each named by its key. It runs any Widget its user can run, or only the Widgets its user picked for it; a Widget outside them is not found for it. It changes no Widget unless its user gave it **Manage Widgets**. It is not a Session: it signs nobody into the website, and a Session's token is not accepted where a key is. Its runs ring no Bell — the caller learns an ending from the press, which answers when the run ends, or by reading the run — though they stay in the run history. Its secret is shown once and can be swapped for a **New Secret**; the key can be revoked, and never expires on its own.
_Avoid_: token (a Session holds one), personal access token, secret (bare), credential

**Manage Widgets**:
The one permission an **API Key** can carry, switched on by its user when they make the key and off otherwise. A key with it makes a Widget, publishes a new version of one, saves and reads its **Listing Fields** and sets the Widget's own **Creator Environment**, all behind the same **Publish Gate** as the website. A key without it only runs Widgets. A key held to picked Widgets manages only those and makes no new one.
_Avoid_: publish scope, CLI access (a key without it already works from a command line), write access, admin key

**New Secret**:
A fresh secret for an existing API Key. The old secret stops at once; the key keeps its name, Spend Cap, Widgets and runs, so its code reads its runs again as soon as it holds the new one. It is how a leaked key is stopped without losing what it made.
_Avoid_: roll, rotate, regenerate (a Covered link is regenerated; a key gets a New Secret), new key (a new key owns none of the old one's runs)

**Spend Cap**:
The most Byssium an API Key may spend in a calendar month (UTC), set by its user and optional. It counts what the key's runs that month cost, so a failed run counts nothing. A press that would pass it is refused and charges nothing; its user is emailed once that month when a key reaches it. It caps one key; the wallet stays one wallet.
_Avoid_: budget (the Run Budget is time, not money), quota, limit (bare)

**Byssium (Ƀ)**:
What Runners prepay for runs, and what runs are priced in: Runners spend it per run, Creators earn it per run. It is counted exactly to the hundredth (0.01 Ƀ): an amount that comes out finer, such as a percentage of a price, is rounded half up to the hundredth before anyone is charged or credited it.
_Avoid_: credits, coins, tokens, currency (Byssium is a prepayment for runs)

**List Rate**:
The published purchase rate — 100 Byssium per dollar, the smallest top-up tier. Every dollar figure shown beside a price is computed at it, plus the viewer's tax where they owe it, so a larger tier only ever beats the figure shown.
_Avoid_: exchange rate (four tier rates exist; the List Rate is the one that is quoted), peg (marketing shorthand for the same number)

**Purchased Byssium**:
Byssium bought in a top-up; spendable, never withdrawable.

**Earned Byssium**:
What Abyss owes a Creator: the full price of each Paid Run of their Widgets, and their share of each **Monthly Access** payment. It is the only Byssium that can be withdrawn, and the only Byssium that can pay for a Plan. No one can buy or transfer it, and it never expires.
_Avoid_: revenue, income

**Subscription Allowance**:
The monthly Byssium grant included with a subscription; spendable on runs, excluded from the wallet balance, gone when the subscription ends. A run spends it first, then the wallet.
Exactly one per paid period: a renewal starts a new period with its own grant; the same period is never granted twice.
_Avoid_: subscription bonus, free coins (the Eloquent model is `SubscriptionBonus` for legacy reasons; the domain term is Subscription Allowance)

**Withdrawable Balance**:
The most a wallet can withdraw now — Earned Byssium that has cleared, minus already-withdrawn, never more than the current balance. It is the only balance shown with a dollar figure, at the **Withdrawal Rate**.
_Avoid_: real balance (that is the whole spendable balance, earned or purchased)

**Clearing**:
The short wait after a run, or a **Monthly Access** payment, before its earning can be withdrawn, the same for every earning and set by the platform. The Creator sees each clearing amount with the date it becomes withdrawable. An earning counts as paid when it clears, so any US tax the law makes Abyss withhold is taken then, or earlier if the Earned Byssium is spent on a run first. An earning whose Creator hasn't given a **Tax Form** waits for it.
_Avoid_: pending, maturing, locked

**Frozen Earning**:
An earning stopped from clearing because the payment processor warned of fraud on the payment behind it, together with everything else that payment paid for. It clears when an Admin releases it, or by itself once 120 days pass with no dispute.
_Avoid_: Payout Hold (the code's name for the service and Admin screen that hold Frozen Earnings; its own wait is set equal to Clearing, so it adds none), freeze (bare), review (bare), pending payout

**Tax Form**:
The form a Creator gives once, as they set up Withdraw, when their Earned Byssium first reaches the minimum withdrawal: a W-9 if they are a US person, otherwise a W-8BEN (W-8BEN-E for a company) naming their country and claiming its treaty rate. It is given through the tax-forms service, never stored by Abyss. Until it is given, the Creator's earnings don't clear and their Earned Byssium can't be spent.
_Avoid_: tax interview, tax info, W-8 (one kind of Tax Form)

**Withdraw**:
A Creator's act of taking Earned Byssium out of their wallet as money, from their Studio's Earnings: any whole amount from the minimum to the Withdrawable Balance, at the Withdrawal Rate, into their own bank account in a **Withdraw-Eligible Country**.
_Avoid_: cash out, payout (the monthly automatic payout, which happens by itself)

**Purchase Withdrawal**:
A buyer's act of taking back a purchase within 14 days of paying: what they haven't used returns to their card. No Creator is touched, except for **Monthly Access**: what returns is taken back from its Creator. Any buyer may do it, and only the law's countries are told of it.
_Avoid_: withdraw (bare; that is a Creator's act), cooling-off, refund (an Admin's act)

**Refund**:
An Admin's act of returning a payment, chosen case by case in the Admin Panel: what is unused, or everything, taken from the Creators it paid or borne by Abyss. Nothing about it is automatic, and it never causes **Payments Paused**.
_Avoid_: reversal (what a dispute does), chargeback (a dispute the buyer's bank decided), Purchase Withdrawal (the buyer's own act)

**Withdraw-Eligible Country**:
A country on Abyss's published list where Earned Byssium can be paid out, by a withdrawal or the monthly payout. It is the country of whoever is paid, meaning where the person lives or where their company is registered, and their bank account must be there too. Where the Creator happens to be doesn't matter. A country joins only when Abyss can pay the full Withdrawal Rate there, every fee paid.
_Avoid_: payout country, supported country, withdrawal country

**Withdrawal Rate**:
The cash value of withdrawn Byssium, set by the platform and published: one rate for every Creator, on every plan. It is lower than what Runners pay for Byssium, and that gap is the whole **Take**. Abyss pays every fee for moving the money, and nothing comes off it: tax the law makes Abyss withhold was already taken when the earning cleared.

**Take**:
The platform's share of what Runners pay, taken once, when a Creator's Earned Byssium leaves as dollars, by a withdrawal or the monthly payout: the spread between the purchase rate and the Withdrawal Rate. It is the same on every plan and every run, whoever brought the Runner, and it is published.
_Avoid_: commission, fee, cut (there is deliberately no per-run cut)

**Reserve**:
What Abyss's Stripe balance always keeps: the Withdrawal Rate for all Byssium not yet used up or paid out, plus a cushion set by the platform. Everything above it is Abyss's own money.
_Avoid_: float, buffer, minimum balance, Payouts Owed (only what is withdrawable now)

**Sweep**:
Abyss paying itself: moving money from its Stripe balance to its own bank, and only what is available above the **Reserve**.
_Avoid_: payout (a Creator's monthly payout), withdrawal (a Creator's)

**Call Price**:
What a run pressed through the API costs on top of the Widget's price. It is a small flat amount set by the platform, paid by the caller from their **Available Byssium** and kept by the platform. It applies to every Widget, paid, free or the caller's own, and a failed run costs nothing, the Call Price included. A run pressed on the website never carries it, and neither do an account's first hundred runs through the API. It is not a share of what the Creator earns, so it is not part of the **Take**.
_Avoid_: API fee, surcharge, commission, per-call fee

**Prime**:
The Runner's monthly subscription — a Subscription Allowance of Byssium each month. It is not a **Plan**; plans are a Creator's, though **Max** includes Prime. (The plan row is named `SENIOR` for legacy reasons; the `JUNIOR` row means no Prime and is not a subscription.)
_Avoid_: Senior, premium, plan (the plans are Pro and Max), member discount (Prime takes nothing off a run's price)

**Subscription State**:
Where a user stands with Prime, or a Creator with their **Plan** — each its own, since a plan is a subscription of its own type beside Prime and never read as Prime. One of: none (never subscribed), active, cancelling (cancelled, keeps its allowance until the period ends), past due (a renewal payment failed, a card update is awaited), lapsed (a past subscription that ended). Served by the platform from the payment processor's own lifecycle events, never derived from dates.
_Avoid_: subscribed / unsubscribed (a boolean cannot say "cancelling" or "past due")

**Available Byssium**:
What a Runner can spend on a run right now — the Subscription Allowance remaining plus the wallet balance, less any Earned Byssium still waiting for its Creator's **Tax Form**, and less the US tax still to be taken when their own earnings clear. A run is gated when its price exceeds it; the shortfall is the difference.
_Avoid_: balance (that is the wallet alone), funds, total balance

**Free Run**:
A run of a paid Widget charged to no one. The Creator grants each Runner up to ten on that Widget for life (`free_run_limit`, a Listing Field); the slot is reserved at the press and handed back if the run fails; it pays the Creator nothing — a Creator-funded giveaway, not a platform subsidy. Served per viewer as the limit and the runs remaining; the Creator's own runs and free Widgets have none. It is an allowance against one Widget, not a price, so the viewer's run price never folds it in.
_Avoid_: trial (nothing expires), free credits (it is not Byssium), promo run, Test Run (the Creator's run of a Candidate)

**Free Widget**:
A Widget whose price is 0. A Widget saved with no price is free too, so every Widget has a price. Its card and its page say Free, and it has no Free Runs.
_Avoid_: unpriced, Ƀ 0, priceless

**Byssium Checkout**:
The one surface for every payment on Abyss: a Runner tops up, subscribes to Prime or buys **Monthly Access**, and a Creator subscribes to a **Plan**. It is opened by a run their Available Byssium cannot cover, deliberately from their Cave, from the Plans, or on a **Link Page**. It closes only once the Byssium has landed, never on the payment processor's word. It never starts a run.
_Avoid_: paywall, top-up dialog, purchase page, funding dialog, plan checkout (the same surface)

**Private Link**:
A private address to one of a Creator's own Widgets: whoever has it can open the Widget, listed or not. Every private Widget has one; a **Pro** Creator can make more, for any of their Widgets, public or private, each with a name. Regenerating one gives it a new address, and the old one stops working; a named one can also be deleted.
_Avoid_: private URL, secret link, unlisted link, share link (a public Widget's address carrying the Creator's ref)

**Covered**:
A state of a **Private Link**, set by one switch on **Pro**, and one answer to who pays on its **Link Page**: whoever opens it runs the Widget on its Creator's account, as a **Guest**, with no sign-up and nothing to pay. A covered run is the Creator's own run, so it is free, earns nothing, and the Creator can open it. Only a run pressed on the link's own page is covered, never one through the API. When Pro ends, no link is Covered, and every Private Link keeps working.
_Avoid_: sponsored, paid by the Creator, free link, client link, guest link

**Link Page**:
The page a **Pro** Creator's **Private Link** opens: the Creator's **Brand**, one Widget, its form and Run, and nothing of the Catalog. Its Creator sets on it who pays: the Creator (**Covered**), or whoever opens it, by each Run at the Widget's price, by **Monthly Access**, or by either. Signing in and paying happen on it, so nobody leaves it to pay.
_Avoid_: Covered page (Covered is one answer to who pays, not the page), client page, portal, landing page

**Monthly Access**:
What a Runner buys on a **Link Page** at the monthly price its Creator set in dollars: every Run of that link's Widget they press on the website for a month, on the Link Page or on the Widget's own page, never through the API. It is one account's, paid by card and renewed each month until its holder ends it; a Creator's change never cuts a paid month short, and a new price is for new buyers only. Abyss keeps a published share of each payment and the Creator gets the rest as **Earned Byssium**. It is not **Prime**, not a **Plan**, and its share is not the **Take**.
_Avoid_: subscription (bare; Prime is the Runner's subscription), membership, client plan, link price (the price is what it costs; Monthly Access is what is bought)

**Guest**:
A person running a Widget through a **Covered** link, with no account. The runs they press are the Creator's; they reach them only through that link, in the browser they pressed them in.
_Avoid_: client (anyone can be a client, and a client is never an account of its own), anonymous Runner, visitor, shadow user, end user

**Human Check**:
The background check that a person is there, at sign-up with an email and on each press a **Guest** makes. Most people never see it; a few tick one box; it is never pictures. It stops plain scripts and is not the wall: the limits, email verification and the **Line** are.
_Avoid_: captcha, reCAPTCHA, Turnstile (the vendor, not the thing), bot check, Guest check (it is at sign-up too)

**Plan**:
What a Creator subscribes to for convenience, management and functionality around their Widgets: **Pro** or **Max**. It never adds Widgets, runs, speed or API access, and never changes the **Take**. A Creator with no plan can still publish, price, share and withdraw; having no plan is shown as Standard, which is not a plan.
_Avoid_: tier, Creator plan (every publisher is a Creator), Free plan, subscription (Prime is the Runner's subscription)

**Pro**:
The plan that lets a Creator make more **Private Links**, opens each on a **Link Page**, lets them switch any of them to **Covered** or give it a monthly price (**Monthly Access**), puts their **Brand** on their Widget pages, run pages, link previews and Link Pages, and keeps a record of every run other people make of their Widgets.
_Avoid_: Studio, agency plan, Creator plan

**Brand**:
A **Pro** Creator's logo with their **Studio**'s name, shown on their Widget pages, run pages, link previews (drawn into the share image), **Link Pages** and shared monthly summaries. When Pro ends it is kept, shown to its owner alone, and returns with Pro.
_Avoid_: badge, white label, branding

**Max**:
The plan that holds everything in **Pro**, **Prime**'s Subscription Allowance each month, and **Spaces**.
_Avoid_: Team, Studio, agency plan, organisation plan

**Space**:
A part of a Max Creator's account with its own name and **Studio Address**, **Brand**, links, domain and run records, picked at the head of their one **Studio**, so separate lines of work stay apart.
_Avoid_: workspace, client space, project, Studio

**Standing**:
What a Widget or a person has when the money Abyss recently kept covers what their runs cost it, the machines they used and the bytes they moved: for a Widget, the **Take** on the prices its runs paid and their **Call Prices**, after refunds, and the **Access Share** of its Monthly Access payments; for a person, the same for the runs they pressed and the Monthly Access they bought, plus their **Plan** and **Prime** fees. A run of a Widget in Standing, or pressed by a person in Standing, never waits in **Line**. A run with neither gets a small base number of runs at once, and any more wait in Line; a run is never refused for it. Only a run the platform ended itself counts for nothing, whatever class a run reports. It is earned by money paid on Abyss, never granted, and nobody is shown it.
_Avoid_: trust score, reputation, credit, tier (no plan grants it; a plan's fee only counts toward it), limit (bare)

**Byte Pace**:
How many bytes runs outside **Standing** may move before the next one waits, refilling over a day: each such person has one, and the platform has one that all of them share. The bytes are a run's outputs, its inputs and what its Widget code sent, counted the same from every Surface. Past it, runs wait and start again as it refills; nothing is refused, and nobody is shown it.
_Avoid_: quota, allowance (the Subscription Allowance and CloudFront's plan allowance), cap, meter, bucket, byte limit

**Rating**:
A one-to-five star verdict one user gives one Widget; a user holds at most one Rating per Widget and may revise it. The `reviews` table stores every Rating, and a Widget's displayed rate is the mean of its Ratings' stars.
_Avoid_: review (when only the stars are meant), vote

**Review**:
A Rating that also carries a written note; `review_count` counts Reviews only. The note is stored, and no page of the website shows it yet.
_Avoid_: comment, rating (when the note is what matters)

**Unrated**:
A Widget that has no Ratings yet; it stays Unrated no matter what its Creator does, since a Self-Rating never counts.
_Avoid_: zero-rated, 0.0, five-star by default

**People Score**:
How strongly people's use says that a Widget works, from zero to one. Each person other than its Creator gives it up to four points: it worked for them, they came back on a later day, they paid for it, they paid again. A person who gave a **Low Rating** gives no points and counts against it. A person is an account, so a guest on a **Covered** link is not one, and a **Stopped** account counts for nothing. A failed run never counts against a Widget, and a run's price is never read. In a search with a query, it decides only between matches that are nearly equal.
_Avoid_: quality score, popularity, rank, browse score, runs score, Wilson score (that is the maths behind it)

**Search Score**:
A number from minus one to one that an Admin sets on a Widget, added to its **People Score**: plus one puts the Widget above every Widget that has none, minus one puts it below every other, and a small value moves it a few places. It is a storefront tool for a small Catalog, and it never acts on a search with a query.
_Avoid_: boost, score (bare), pin, featured

**Catalog Score**:
The number that orders the Catalog when a visitor types nothing: a Widget's **People Score** plus its **Search Score**, newest first on a tie. The api alone computes it, and nobody outside the Admin Panel sees it.
_Avoid_: ranking, score (bare), final score, browse score

**Unread**:
A Notification its user has not opened yet — opened by following it, or all at once by "Mark all as read". Opening the Bell makes nothing Unread read.
_Avoid_: new (a different thing), seen

**Publish Reminder**:
The one Notification and one email a Creator receives when a Widget whose Test Run succeeded is still not published a while later — once per Widget. The row's stored type still reads `Widget-Deployment-Required`; the word is Publish.
_Avoid_: deployment required, deploy

**Paid Run**:
A run that earned its Creator Byssium: it succeeded, someone other than the Creator ran it, it was not a Free Run, and the Widget had a price. How the Runner funded it — wallet or Subscription Allowance — does not matter, because the Creator earns the same either way. It belongs to the week it settled in, not the week it was pressed.
_Avoid_: paid non-owner run (the same thing, said longer), authentic run, sale, purchase (a purchase is a top-up)

**Earning Creator**:
A Creator with at least one Paid Run in a given week, counted once however many they had. A seed account is the platform, not a Creator, and is never one. Headline number.
_Avoid_: active creator (ambiguous with Shipping Creator), seller, merchant

**Shipping Creator**:
A Creator who ran a Test Run or Published in a given week, counted once — the Creator using what the platform sells. A seed account is never one. Headline number.
_Avoid_: active creator (ambiguous with Earning Creator), publisher

**Cash In**:
The dollars the platform actually received in a given week — top-ups, Prime payments and **Monthly Access** payments as charged, minus refunds and chargebacks, before the payment processor's fees — counted in the week the processor confirmed each one, and always shown split by what was paid for. Headline number.
_Avoid_: revenue (the Take is revenue; Cash In includes Byssium the platform still owes back as runs and payouts), MRR (Prime alone), sales

**GMV**:
The Byssium Creators earned in a given week, through Paid Runs and through **Monthly Access** payments. Counted in Byssium; a dollar figure beside it is at the List Rate and is a ceiling, since larger tiers buy Byssium for less.
_Avoid_: revenue, Cash In (money the platform received, not money that moved to Creators)

**Payouts Owed**:
The sum of every wallet's Withdrawable Balance, valued at the Withdrawal Rate — what the platform would pay if every Creator withdrew everything today. Internal only.
_Avoid_: creator balance, liabilities (unqualified)

**Covered Run**:
A run pressed on a **Covered** link, counted in the week it ended — runs delivered on Creators' links, the layer's own number, shown beside **Paid Runs**. It is the Creator's own run, so it is never a Paid Run and never in **GMV**.
_Avoid_: sponsored run, free run (a **Free Run** is a Runner's run of a paid Widget charged to no one), client run

**Access Run**:
A run that **Monthly Access** paid for, counted in the week it ended, beside **Paid Runs** and **Covered Runs**. It is its Runner's own run, and it is never a Paid Run: the month's payment is the earning, not the run.
_Avoid_: subscribed run, paid run, free run, member run

**Access Share**:
Abyss's share of each **Monthly Access** payment, set by the platform and published, with every fee for taking and moving the money inside it. It is not the **Take**, which is the spread on Byssium only.
_Avoid_: commission, fee, cut, Take (on Monthly Access)

**Surface**:
What made a request — the website or an API key. A command-line tool that holds an API Key is the API, like any code that holds one. Fixed on a run, on a Project Version and on a Widget when it is created, decided by the platform from the credential used, never by what a client says. A row the platform makes itself, with no credential, has none, rather than a guessed one.
_Avoid_: channel (it blurs Surface and Attribution), source, platform, client

**Creator Link**:
A link to a Widget that its Creator hands out — a **Private Link**, or the Creator's share link (a public Widget's address carrying the Creator's opaque ref). Arriving through one is what makes a Runner the Creator's own for that Widget.
_Avoid_: referral link, affiliate link, private URL (the private link is one kind of Creator Link)

**Attribution**:
Who brought a Runner to a Widget: the **Creator** (the Runner first reached that Widget through a Creator Link), the **Catalog** (everything else — search, browsing, and any traffic the platform itself earned, such as a search engine or a post), or **First-party** (the Widget is the platform's own). Decided once per Runner and Widget, at first touch, and kept for good. It is about who did the finding, not about where on the web the visitor clicked; that second question is marketing's, answered with campaign tags.
_Avoid_: channel, source (marketing's question), referral

**First-party Widget**:
A Widget Abyss builds and keeps healthy itself, published from an **Abyss Member**'s account. It is listed in the Catalog like any other and carries Abyss's mark where another Widget carries its Studio's **Brand**. It never counts toward any Creator number. It is not seed content. "First" says whose it is, not when it came: the Widgets the founders build and the ones they port in are all First-party.
_Avoid_: house widget, official widget, seed widget, Made by Abyss Widget

**Abyss Member**:
An account of a person who builds Abyss, marked as such by the platform. Every Widget it publishes is a **First-party Widget**. The account earns and withdraws as any Creator's does, and it is never counted as an **Activated**, **Shipping** or **Earning Creator**. A run from it never activates another Creator. It is not a seed account: a seed account is the platform and its Widgets are never listed; an Abyss Member is a person and their Widgets are.
_Avoid_: staff account, team account, official account, member (bare)

**Template**:
A **First-party Widget** whose project Abyss publishes for anyone to copy. A Creator starts from it, changes it and publishes a Widget of their own; that Widget is the Creator's and has no tie to the Template. Abyss shows the project by its own choice, outside the platform; the platform still shows no one a Widget's **Source**. The word is the one automation people already use for a flow they copy and change.
_Avoid_: starter, sample, example widget, pattern (a way of working, not a thing), boilerplate

**Held Port**:
A **First-party Widget** that Abyss ported from one maker's public tool and holds until that maker claims it. Its description names the tool and its maker and says that it is a port. It may be listed or Private, and the bar a **Template** must pass does not bind it. When the maker claims it, it becomes that Creator's own Widget and is First-party no longer. The runs before the claim stay First-party, so the Creator's own numbers start at zero.
_Avoid_: demo, gift, seed

**Port Claim**:
What the maker of a **Held Port** does to take it: they sign in or sign up through its claim link, and the Widget moves to their account, already published, as it stood. A claim link works once.
_Avoid_: transfer, import, adopt, claim (bare: in the Widget Runtime a machine claims a run)

**Campaign Tags**:
The `utm_` labels, the referring site's domain and the landing page's path from the first page a person opened, saved on their account when they sign up. They answer marketing's question, which campaign brought someone, never **Attribution**'s. The browser keeps them only where the person's **Analytics Choice** is yes.
_Avoid_: UTMs (only five of the seven), source, channel

**Default-On Country**:
A country where Google Analytics loads without asking, because Abyss has checked that its law allows analytics with notice and a way to turn it off. Every other country is asked first, and so is a location Abyss can't place.
_Avoid_: opt-out country (it reads as a person who opted out), non-EU, allowed country

**Analytics Choice**:
A person's yes or no to Google Analytics, kept in their browser. In a **Default-On Country** it starts as yes; anywhere else it starts unanswered, which counts as no. A Global Privacy Control signal is a no. The banner, or the Cookies page, changes it. Everything a page sends only to measure what people do follows it: Google Analytics, **Campaign Tags** and the Checkout's step reports. What Abyss's server counts from requests a page makes anyway, a **Visit** or an **Active User**, does not.
_Avoid_: consent (the law's word for the yes alone), cookie choice, tracking preference

**Visit**:
One arrival at Abyss's site from outside it: a link, a search result, a typed address or a bookmark. Abyss's own server counts it from the page request itself, so it counts every arrival, whatever the **Analytics Choice**. Moving between Abyss's pages is not a new Visit; coming back later is. Abyss never recognises who made a Visit, so Visits are never a count of different people. A Visit that lands on a **Covered** page is a Covered-page Visit, counted apart.
_Avoid_: visitor (Abyss counts arrivals, never people; and see Explorer, Guest), unique visitor, session, page view, hit

**Open to Search**:
What a Widget's page is when search engines may show it: the Widget is in the **Catalog**, it has an **Example Run**, and no Admin has taken it out of search. The api decides it once, and the sitemap and the page's own rule for crawlers both read that answer. A Studio is Open to Search once it holds one such Widget. A Widget can be listed and not Open to Search; a private Widget and a seed account's Widget never are.
_Avoid_: indexed, indexable, listed (listed means in the Catalog), SEO-enabled, crawlable (a crawler can reach a page that it may not show)

**Search Visit**:
A **Visit** that a search engine sent: the person pressed a result on a search engine's page. A Search Visit that lands on a page that offers Widgets (a Widget's page, the Catalog, a Studio) says whether search works for Runners; one that lands on a page that offers Abyss (the landing page, the Docs, Pricing, the FAQ) says the same for Creators. It is read each week and is never a target on its own: marketing is still judged by **Activated Creators**.
_Avoid_: organic traffic, organic visit, SEO traffic, search click (a click is what the search engine counts; a Visit is what Abyss counts)

**Active User**:
A person who used Abyss while signed in on a given day, because their browser called the api at least once that day. It is counted per day, per 7 days and per 28 days, whatever their **Analytics Choice**. Calls made with an API key count as API callers, never as Active Users.
_Avoid_: DAU or MAU (those are the counts, not the person), online user, active creator (see Shipping Creator, Earning Creator)

**Compliance Trigger**:
A point named in advance at which Abyss must act on law or tax, because no adviser watches for it: hire an adviser for one question, register for a tax somewhere, or stop selling there. It is a measure crossing a threshold, such as Cash In in a month, or an event, such as the first non-US Creator being paid. The Admin Panel shows each one beside how close it is, and the founders are emailed when one is reached.
_Avoid_: threshold (a threshold is one kind of Compliance Trigger), alert (the email sent when one is reached), counsel trigger

**Filing Calendar**:
The dates Abyss owes a tax deposit, return or form, each with the amount Abyss's own records say is due, shown on the Admin Panel beside the Compliance Triggers. It lists the VAT return of each place Abyss is registered in; one outside the EU and the UK carries no amount, which Stripe Tax's report holds; the founders are emailed a week before each. The founder files; the tax-forms service files its forms.
_Avoid_: tax calendar, deadlines, reminders

**Harness Vintage**:
The Harness Contract version a given run actually executed with — observable via the harness version line; consumers must tolerate markers absent in older vintages, and fields absent from them. On Fly the harness is injected into each Staged Member when it is staged, so a new vintage reaches a member at its next stage; on the Local Substrate it is baked into the runtime image. Old payloads therefore keep arriving after a change: what the platform must do with them is part of the design, not a migration to schedule.

**Fly Machine**:
A hardware-virtualized micro-VM on Fly.io in which exactly one widget run executes at a time. The machine is both the isolation boundary and the unit of pooling.
_Avoid_: "container", "pod", "sandbox" (a Machine is none of these)

**Machine Pool**:
The set of **Staged Members** parked for one **Widget App**, each holding one image of the widget already unpacked — the image is a fact of the member, not of the widget, and a run is served only by a member of the image it executes. Members are reused across runs; depth is per-widget and derived from that widget's **Offered Load**, bounded by its **Depth Envelope** and granted out of the **Platform Machine Budget**. An operator may assert an envelope; the *granted* number is always the allocator's.
The backend module `MachinePool` owns each member's lifecycle — fill, stage, lease, Wake, recycle, reap. It runs no container engine and holds no run-signing material; per-run secrets are minted at **Claim** time, not parked in members.
_Avoid_: "Sandbox Pool", "warm pool" (nothing in this pool is running), "Pool Manager" (no code has that name)

**Staged Member**:
A stopped pool member that is dispatch-ready: staged off the request path with one image and machine-scoped material (its **Claim Token**), and settled, so dispatch needs nothing but a start. It records the image it was staged with, and is kept for as long as that image is the live one or the Candidate's — so the machine that ran a Test Run is, after Publish, the machine that serves the first Runner, with no work between. A member of any other image is destroyed by the sweep.
_Avoid_: "warm member" (nothing is warm; it is prepared); "the widget's member" (a member is a member of one image of the widget)

**Quarantined Member**:
A member the **Machine Pool** has judged out of contract and destined for destruction — a **Wake** that never received a **Claim**, or a member that failed recovery twice. A *state*, not a flag on another state, so that exactly one owner is responsible for it. Holds a machine until recycled, so it counts toward the **Platform Machine Budget** but toward none of the admission bounds.
_Avoid_: treating quarantine as a pause (nothing leaves it except destruction)

**Staging Member**:
A created-but-not-yet-settled member: the machine exists on Fly and bills, but has not reached `stopped`, so it is never leased. Its lease row is written the instant the machine exists — ahead of the settle — because the **Reaper**'s machines sweep enumerates **Widget Apps** from that table, and a machine with no row is beyond every reconciliation path there is. A settle that never lands leaves a Staging Member, which the sweep then adopts (it settled late) or recycles (it never will). A member the scheduled fill or the sweep's refill creates ahead of demand stays a Staging Member through one boot with no **Claim Token** and the park that gives it one, so its first **Wake** starts a machine booted once; its row carries no token hash until then, and the sweep recycles a settled one that has none rather than adopt a member no run can **Claim**. **Burst Fill**'s members are never booted before their Wake.
_Avoid_: calling one a **Staged Member** (a Staged Member is settled and dispatchable — that is the whole distinction); "pending member"

**Wake**:
Dispatching a run by starting a **Staged Member** — the start and nothing else; all per-run personalization is deferred to the **Claim**. One act, owned by the **Machine Pool**: leasing the member, recording which member the run is on, starting it, counting the **Pool Hit**, and arming the no-claim window are a single indivisible step, whether the Wake is a run's first or a retry.
_Avoid_: describing Wake as delivering the Run Environment (it delivers nothing); reading "the start and nothing else" as *orchestrating* nothing else (it describes what the guest receives, not what the backend does)

**Claim**:
The booted member's first act: presenting its **Claim Token** to the backend and receiving the **Run Environment** (callback identity, presigned I/O, interface). The backend answers only a member whose recorded image is the image the run executes; a mismatch is a refused Claim, never a run of the wrong code. The Claim doubles as boot confirmation — a Wake with no Claim within its window is a failed boot.
_Avoid_: "poll" (it happens exactly once per run)

**Claim Token**:
Machine-scoped, single-use credential staged into a member at park time and rotated at every re-stage. Exchanging it for one pending run's environment is the only power a compromised member holds. Because it is staged at park rather than at **Wake**, it is readable for as long as the member is parked and becomes valid the moment the member is leased.
_Avoid_: "fleet secret" (there is none); describing it as short-lived (it is minted at park, not at dispatch)

**Depth Envelope**:
The per-widget floor and ceiling an operator may set on a **Machine Pool**'s depth — a *request*, not a guarantee, because the allocator clamps it to what the **Platform Machine Budget** can grant. Floor equal to ceiling pins a depth; ceiling 0 is the cold path, under which a member is recycled the instant its run settles instead of being parked, so the widget genuinely never holds a machine and every run pays a **Cold Create** by design. What the allocator actually granted is recorded alongside the request, because an operator who asked for three and received two must be able to see why.
_Avoid_: "pool depth override" (it does not override the derivation, it bounds it); reading a floor as reserved capacity

**Platform Machine Budget**:
The total number of Fly machines the platform will hold across every **Widget App**, sized below the Fly org's cap — which counts *stopped* machines, so parked depth spends it just as running depth does. The bound is on creation, not on dispatch: a **Wake** moves a member between states without adding a machine, so only fill and **Burst Fill** spend the budget. Allocated deterministically — floors first, then elastic depth by descending derived target — so that when it is exhausted, which widgets fall to the cold path is a decision the platform made and can report, rather than an artifact of catalog ordering surfacing as a transient error. It rises by one for each plan floor — the floor a plan holder's widget keeps while it ran in the last ~90 days, past the 7 days every widget gets — and each plan floor is funded from that addition, so it never takes a free widget's.
_Avoid_: "the Fly limit" (the budget sits below it, with reserved headroom for Burst Fill); conflating it with the **Global Breaker** (that bounds concurrently *running* machines; this bounds machines that *exist*)

**Admission**:
The decision of whether a run may start *now*, taken at the **Lease** and composed of the four bounds below — the **Concurrency Cap**, the **Breaker Share**, the **Global Breaker** and the **Wake Batch** — asked in that order, most specific first. It answers with a deferral or with a member; it never rejects a run. Because its four counts are read from the lease table and then *spent* against, the counting and the lease that spends are one serialised critical section: a single **Admission Gate** row locked for the length of the lease, so two admitters cannot pass the same bound.
_Avoid_: "admission control" / "throttle" (a throttle rejects or paces by time; this defers by occupancy); "the admission gate" for the *decision* — the gate is the lock, the decision is Admission

**Global Breaker**:
The platform-wide cap on machines *running* at once across all Widget Apps: a money and blast-radius tripwire, sized far above expected peaks. When it is full, runs make a **Capacity Wait**, and the next machine goes to the person running the fewest.
_Avoid_: conflating it with the per-widget **Concurrency Cap** (product dial)

**Breaker Share**:
The most of the **Global Breaker** one person may hold at once: half, in **Standing** or not.
_Avoid_: per-person limit, quota, **Concurrency Cap** (that one is per Widget)

**Creator Environment**:
The creator-managed slice of the **Run Environment**: per-widget variables (Widget settings) overriding the creator's account-global defaults, carrying the creator's own third-party credentials (LLM API keys and the like). Encrypted at rest, delivered only at **Claim**, never parked in a member. The platform funds none of it and platform-reserved names cannot be shadowed.
_Avoid_: "widget secrets" (to the guest they are plain env vars; the secrecy is at rest and in delivery, not in the guest)

**Run Budget**:
How long a guest may execute after its **Claim**, and how much Widget code may send while it does — the deadline the **Run Environment** carries and the **Runtime Harness** enforces in-guest as rung one of the kill ladder. It is the only stop a pressed run has: nobody cancels one — not its Runner, whose refunded cancel would spend a Creator's API keys for free, and not its Creator, whose worst case is one budget of their own spend.
_Avoid_: "cancel run" (there is none); "job deadline" (ambiguous with the Dispatch Budget); "Byte Reaper" (the **Reaper** settles stuck runs; a run past its bytes is Budget Exceeded like one past its time); assuming it covers the build (it begins after the image exists); assuming it covers the output push (see **Upload Window**)

**Budget Exceeded**:
A run ended by its **Run Budget** rather than by its own code — an outcome, not a fault, so it refunds without freezing the widget on first occurrence. A widget whose recent runs are *nothing but* Budget Exceeded is frozen: at that point it is a cost sink rather than a slow widget, and the freeze is how its creator is told so.
_Avoid_: reporting it as a widget error (it says nothing about the creator's code, and the published limit promises only that the run is stopped and the user refunded); conflating it with a reap (the **Reaper** ends a run whose *phase* stalled, this one ran and was stopped)

**Run Outcome**:
How an ended run is classified — **widget fault** (the creator's code), **platform fault** (the platform's own machinery: a reap, a lost callback, an output push that failed) or **Budget Exceeded**. Every class refunds; a Widget freezes on a streak of any one class — nothing but widget faults, nothing but Budget Exceeded, or nothing but platform faults the guest reported itself. The class a guest reports is its word, so Standing reads the **Ending** instead: a run's machine time counts unless the platform ended it itself. What a run ended *as* is decided once, at settlement, from what the run reported — never re-read from its message afterwards. **Every** ending is classified, including the ones that never reached a guest: a build that failed, a submit that threw, a stale row the **Reaper** took. Those are platform faults — all but a **Scan Gate** block on the Widget's own layers and a build that failed installing the Widget's own dependencies, which never started either but are widget faults; only the Creator reads the line such an install stopped at — and a run that carries a reason its creator cannot read is not settled, only stopped.
_Avoid_: inferring the class from the error message anywhere but the one place that bridges older **Harness Vintage** payloads; treating "failed" as a single thing (three endings, and only one is about the widget); calling a platform fault a widget error because the guest's own words said so; treating "settled" as something only a callback can do

**Run Code Time**:
How long the widget's own code ran: python start to python exit, as the harness sees it. Imports count — the creator chose them. It is the creator's time, and the one part of a run no platform target covers.
_Avoid_: calling it "run duration" (`RunDurationSeconds` is Claim to settlement, which holds platform time too)

**Platform Overhead**:
The platform's headline speed number: from the moment the api holds the whole Run request to the run's settlement, minus **Run Code Time**. Computed by the Admin Panel from every run's stamps. The Runner's file upload is outside it — it is the Runner's own connection, not the platform.
_Avoid_: "latency" or "cold start" unqualified; quoting a full click-to-result time as the platform's speed (that is **Runner Wait**)

**Stage Stamp**:
A moment in a run only the guest can see — harness started, claimed, python started, python exited, callback sent — reported by the harness in its signed callback and kept on the run. Together with the api's own stamps they cut a run into **Run Stages**. A run from an older **Harness Vintage** has none, and shows only the api's side.
_Avoid_: reading stamps out of the run's logs (the logs keep only their tail, and a widget can print anything); confusing them with the log markers, which stay diagnostics

**Run Stage**:
One step of a run between two stamps: Request, Wake, Claim, Input, **Run Code Time**, Uploads, Settle. Uploads is everything the harness does between the code ending and the callback — the output limit check, the output push and the log capping — not the push alone. Every stage except Run Code Time is **Platform Overhead**. They exist to show where a run's time went, for the platform's own monitoring; none is a promise to a Runner.
_Avoid_: "segment" (the probe's word, numbered and finer-grained); calling a stage an SLO

**Creator**:
A person or team who publishes a Widget — for their own Runners, for a client, for the Catalog, or for agents — and earns Byssium when other people's runs or Monthly Access pay for it. Most are Python developers; the word covers a freelancer delivering a tool to a client, a business running a commissioned tool, and a domain expert who had the code written for them.
_Avoid_: developer (too narrow — a Creator need not have written the code), seller, builder, innovator, merchant

**Runner**:
Whoever runs a Widget: a person through the form, or their code or agent through an API Key. A run is paid from the Runner's Byssium or Subscription Allowance, unless it is a Free Run or Monthly Access covers it. A Guest on a Covered link is not a Runner.
_Avoid_: user, consumer, buyer, end user

**Explorer**:
A Runner at the earliest funnel stage — browsing the Catalog, signed in or not, without having run anything yet. A commitment stage, not a third audience.
_Avoid_: visitor, browser

**Admin**:
A person with an `admin_users` row who signs in to the Admin Panel; distinct from a user of the platform.
_Avoid_: admin user, operator, staff

**Admin Panel**:
The separate Laravel application that operates the platform. It reads the api's database directly. It changes the platform's state only through the api's signed internal endpoints, and edits directly only the content that no api rule governs.
_Avoid_: back office, dashboard, CMS, "the admin" for the app

**Catalog**:
The Widgets a stranger can find: approved, not private, not Stopped, with a live build that did not fail, and owned by a person still in reach — never a seed account. First-party Widgets are in it. Search and browse read only the Catalog, and a Widget leaves it the moment any of these stops being true. It is the word of sessions, code and the Admin Panel only: a person sees the place as "Widgets" (the page at `/widgets`, reached by "Browse widgets"), and a Widget in it as "listed".
_Avoid_: inventory, listings, indexed docs (the search index is a copy of the Catalog, not the Catalog itself)

**Run**:
A single execution of a Widget by a Runner. Whatever it costs is reserved at the press; the Run advances through working states (queued, building, submitted, running) and settles in exactly one of two terminal states — **succeeded** or **failed**. A succeeded Paid Run pays its Creator; a failed Run refunds what it reserved, always. A Run that the platform can no longer see into is *unavailable* — a viewing condition, not a lifecycle state.
_Avoid_: job, task (infrastructure words — a Run is the domain event), execution (ambiguous with the runtime internals)

**Field**:
One typed input in a **Widget Interface**: text, text area, number, radio, checkbox group, select, date or file. Its name is the environment variable the run receives. Fields and the **Creator Environment** share that one namespace, so a Creator Environment name can never shadow a Field's name or a platform-reserved name.
_Avoid_: input (ambiguous with the submitted value), control (a UI primitive, not the domain concept)

**Output Folder**:
Everything one Run produced, as one folder of files and sub-folders laid out exactly as the Widget wrote them. The Runner never sees the folder itself, only its contents. An HTML file in it previews as if the Runner had downloaded the folder and opened that file on their own computer: what it references resolves anywhere in that Output Folder and nowhere outside it, and it never reaches the Runner's account or another Run.
_Avoid_: folder output (for a sub-folder inside it, say sub-folder), outputs (alone, which names the run page's last stage)

**Output Manifest**:
The file tree of a Run's **Output Folder** (paths, sizes, node types), captured once when the Run settles and served with the Run thereafter; the ground truth of what a Run produced.
_Avoid_: folder structure, artifacts list (the harness's self-reported `result.json` field, which is not trusted as the source)

**Notification**:
News for one user about something that happened to them or their Widget while they were not looking — for example a Widget went live, faulted, froze or thawed; a Run of theirs ended somewhere they were not watching. What a user does themselves, or watches happen, is never a Notification: a Run in progress is not news, and a Run whose ending its Runner saw on screen is not news either. A Notification is news, never a task: reading it means it was heard, and whatever still needs doing lives on the Widget's page as a **Notice**. The platform decides what is news: a Run is born read and becomes Unread only when it ends; every type the platform emits is on one list.
_Avoid_: alert, activity, message, feed item, task

**New**:
A Notification that arrived since the user last looked at the Bell — opening it or closing it is the look. The platform keeps when that last look was and counts New from it; the badge counts these and nothing else.
_Avoid_: unseen, unread (a different thing)

**Bell**:
The navbar entry that holds a signed-in user's Notifications, newest first. Its badge counts what is **New**, and each **Unread** one is marked in its row, so a Notification can be read but still New, or no longer New but still Unread.
_Avoid_: inbox (as a UI name), notification center, feed, activity log

**Notice**:
A message only a Widget's Creator sees on that Widget's page, about a problem that is still true while it stands — today, **Frozen**. A Notification says something happened; a Notice says it is still so, and goes away when it stops being so. A Notice is never raised on a guess.
_Avoid_: banner, alert, warning
